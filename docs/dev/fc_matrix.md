Audience: developers/agents working on `src/features/functional.py`, `src/pipeline/mask_fc.py`, and `src/pipeline/build_fc_matrix.py`.

This file covers turning WashU's already-computed functional-connectivity CSVs into a lesion-masked feature matrix. For the equivalent lesion-matrix pipeline, see `docs/dev/lesion_matrix.md`. For the models that consume the final matrix, see `docs/dev/models.md`. For "how do I run this", see `docs/guides/fc_matrix_building.md`. ## `src/features/functional.py` — FC lesion masking (implemented, two decoupled pipelines)

**Goal**: for each WashU subject, mark as missing (`NaN`) the rows/columns of FC-matrix nodes (parcels) whose territory substantially overlaps the subject's lesion — same operation Siegel et al. 2016 and Griffis et al. 2019 apply on this same WashU cohort. FC input: `data/clinical_connectome/derivatives/UNIPD/WashU/features/<subject>/func/*_FC-pearson_atlas-<combo>.csv`, node×node Pearson matrices for 12 atlas combos (`Yan{100,200,300,400}TianS{1,2,3}Buckner7N`), space `MNI152NLin6Asym`.

**Atlas source**: `Atlases/fmriprep/atlas-<combo>/` on the EBRAIN server (`/data/corbetta/Clinical_connectome/Atlases/fmriprep/`) — already BIDS-Derivatives-formatted (`*_dseg.tsv` label lookup + `*_space-MNI152NLin6Asym_dseg.nii.gz` native 1mm + `*_res-2_dseg.nii.gz` 2mm), generated by XCP-D/AtlasPack conventions. Verified against the real WashU FC CSVs: node order and count in `_dseg.tsv` match the CSV header/index exactly for at least one combo (`Yan200TianS2Buckner7N`, 239 nodes) — the `_res-2` (2mm) volume is used directly since it matches WashU's lesion mask resolution, no atlas resampling needed for this dataset. The 12 combos (tsv + res-2 nii.gz only, ~2MB total) are committed at `assets/atlases/fmriprep/atlas-<combo>/`, same precedent as the other reference atlases already under `assets/atlases/`.

**Methodology decided (no custom parcellation function)**: rather than a hand-written voxel-loop (as `src/features/lesion.py` does for lesion masks, `docs/dev/lesion_matrix.md`), parcel coverage is computed by reusing `nilearn.maskers.NiftiLabelsMasker` with the same two-masker pattern XCP-D itself uses for its own `min_coverage` BOLD-coverage thresholding (`xcp_d/interfaces/connectivity.py`, class `NiftiParcellate`): one masker with no `mask_img` (total voxel count per parcel), one with `mask_img=healthy_img` (voxel count restricted to non-lesioned voxels) — the ratio is `parcel_coverage`. A parcel is "compromised" when `parcel_coverage < min_coverage` (default 0.5, matching both XCP-D's own default and the field-standard overlap threshold for stroke lesion studies — Lesion Quantification Toolkit, Griffis et al. 2021). Compromised nodes' rows/columns are matched by **node name** (from the atlas's own `_dseg.tsv`), never by column position.

**NaN, not zero, at the masking step — imputation deferred to a separate later step**: literature review across this exact WashU/Corbetta lineage shows the field converged on marking compromised entries as missing (`NaN`), not on zeroing them directly. Griffis et al. 2019's own methods text is explicit about *why* zero shows up downstream anyway: *"Because the PLSC approach cannot accommodate missing values, functional connectivity between parcels that had been excluded ... was set to 0"* — i.e. `NaN` is the correct/honest representation of "not computable", and a concrete fill value is substituted only immediately before a method (PLSC/PCA/UMAP) that cannot itself accept missing values. Neither `sklearn`'s `PCA` nor `umap-learn` (the implementations already registered in `REDUCTION_METHODS`, `docs/dev/models.md`) tolerate `NaN` natively, so this project follows the same two-stage split: `src/features/functional.py` marks compromised entries `NaN` and stops there; a separate, explicitly-configurable imputation step (planned: `NAN_IMPUTATION_STRATEGIES` registry, default `"zero"`, same registry-over-hardcoded-dispatch precedent as `PARCEL_AGGREGATIONS`/`REDUCTION_METHODS`) runs only immediately before `dim_reduction.py`, logging how many values it filled in — never hidden inside a masker/reduction call.

**Two non-obvious bugs found and fixed while validating this against real WashU data** (both would have silently corrupted results if shipped as-is; regression-tested in `tests/unit/test_features_functional.py`):

1. **Silent `uint8` overflow in the voxel-counting trick**: computing "voxels per parcel" via `NiftiLabelsMasker(strategy="sum")` on an all-ones counting image requires that image to have a wide-enough integer dtype. With `uint8`, the sum wraps at 256 (e.g. a 695-voxel parcel reports 183 = `695 mod 256`) — silently, no error, no warning. Fixed by using `int32` for the counting image.
2. **A fully-lesioned parcel disappears from the masked masker's output instead of reading 0**: `NiftiLabelsMasker(mask_img=healthy_img)` drops any label with zero surviving voxels entirely (`labels_` shorter than the unmasked masker's), rather than returning a 0 count for it — naively dividing the two makers' outputs by position would either crash (shape mismatch) or silently misalign every later label. Fixed by indexing both maskers' results by their own `labels_` (never by position) and treating an absent label as `coverage = 0.0` explicitly.

**Two pipelines, deliberately decoupled — including at the config level** (own dataclass/loader each in `src/analysis/build_config.py`, `docs/dev/lesion_matrix.md`; own CLI script, own `jobs/run_*.sh`, own output tree, own `runs.csv`):

1. **`src/pipeline/mask_fc.py`** (`config/pipelines/mask_fc.json` → `MaskFcConfig`/`load_mask_fc_config`) — the only pipeline that ever touches a lesion mask or an atlas. For each `atlas_combo` in the config's `atlas_combos` list (processed sequentially, one `mask_dataset_fc()` call per combo): discovers subjects with both a lesion mask and an FC file for that combo (`discover_subject_files`, built on the shared `src/features/subject_discovery.py::discover_files_by_subject` also used by `src/features/lesion.py` — a subject with FC but no lesion mask is a known, legitimate per-subject gap, logged as a `WARNING` and skipped, never a hard stop for the whole run, per `docs/guides/datasets.md`'s "sulla maggior parte" coverage note; a subject excluded by the config's `group_filter` — e.g. a WashU healthy control, which structurally never has a lesion mask — is reported separately as `excluded_by_group`, never conflated with the missing-lesion case, see `docs/guides/fc_matrix_building.md`), resamples each subject's lesion onto the atlas grid, computes parcel coverage (`compute_parcel_coverage`, the `nilearn.maskers.NiftiLabelsMasker` double-masker pattern above), `NaN`-masks the FC matrix by node name, and **writes the masked matrix to disk as-is** — `data/derived/features/masked_fc/<combo>/<subject>_masked_fc.csv`, a human-inspectable intermediate artifact, independent of how it's later vectorized. Also writes a per-combo `mask_summary.csv` (subject_id, n_compromised_nodes) - the raw material the per-subject exclusion threshold decision was based on (see "Settled, not open work" below).
2. **`src/pipeline/build_fc_matrix.py`** (`config/pipelines/build_fc_matrix.json` → `BuildFcMatrixConfig`/`load_build_fc_matrix_config`) — reads *only* the already-masked CSVs `mask_fc.py` wrote (`masked_fc_root/<combo>/*.csv`); no lesion mask, no atlas, no raw FC data touched here, by design. For each `atlas_combo`: vectorizes each subject's masked matrix to its upper triangle (excluding the diagonal — the matrix is symmetric with a non-informative diagonal of 1.0), asserts every subject's edge labels match exactly before stacking (`stack_fc_vectors`, never assumed), drops constant edges (`drop_constant_edges` below), and writes the result via the existing `src/utils/artifacts.save_matrix`/`load_matrix` pair (same atomic-write artifact format already used by `build_lesion_matrix.py`: `matrix.npy`/`metadata.csv`/`config.md`/`manifest.json`, plus an `edge_names.npy` extra array) to `data/derived/features/fc_matrix/<combo>/<date>_<session_name>/`. The matrix still has `NaN` in it (compromised edges) — imputation to a concrete fill value is deliberately out of scope here, see below.

**`drop_constant_edges`** (in `src/features/functional.py`): an edge with **any** `NaN` is never evaluated for constancy — kept unconditionally. Among fully-observed edges only, one with an identical value across every subject is dropped. Unlike the binary lesion-matrix case (`_drop_constant_features`, `docs/dev/lesion_matrix.md`, where constant all-zero columns are common and unremarkable), an exactly-identical *continuous* FC value across every subject is not expected — `build_fc_matrix.py` logs any drop at `WARNING` (with the edge name and shared value, worth a human look) and logs `INFO` when none are found (a routine, expected outcome, still explicitly confirmed rather than silently skipped).
